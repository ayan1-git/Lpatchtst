# Plan: Implement Data-Driven Bar Density for Walk-Forward Folds

The goal is to reduce the number of assets skipped during fine-tuning due to "bar-level leakage" by dynamically calculating the calendar gap between training and validation sets based on the actual bar density of the dataset.

## 1. Update Configuration
- Add `GAP_MARGIN_DAYS` (default: 3) and `MIN_GAP_DAYS` (default: 7) to `config.py` to allow tuning the gap safety margin.

## 2. Modify `make_date_aligned_folds` in `train.py`
- Update the function signature to accept an optional `avg_bars_per_day: float | None`.
- Implement the new `gap_days` calculation logic:
    - If `avg_bars_per_day` is provided:
        - `gap_days_raw = math.ceil(config.LOOKBACK_WINDOW / avg_bars_per_day)`
        - `gap_days = max(gap_days_raw + GAP_MARGIN_DAYS, MIN_GAP_DAYS)`
    - Else (fallback): use the existing `BAR_HOURS`-based heuristic.
- Log the chosen `gap_days` and the basis (data-driven vs heuristic).

## 3. Update `train()` orchestrator in `train.py`
- After `process_dataset` creates `asset_data_list`:
    - Compute the bar density for each asset as `len(dates) / len(dates.normalize().unique())`.
    - Calculate the global `avg_bars_per_day` as the **median** of these per-asset densities to ensure robustness against outliers.
    - Log the calculated `avg_bars_per_day`.
- Update the call to `make_date_aligned_folds` to pass the calculated `avg_bars_per_day`.

## 4. Verification
- The per-asset guards in `finetune_fold` (`gap_bars >= config.LOOKBACK_WINDOW`) will remain as the final safety check, ensuring no leakage is introduced regardless of the global average.
- Verify that fewer assets are skipped across folds while maintaining the leakage constraint.
