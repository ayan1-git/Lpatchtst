# Plan: Align Tokenizer Input and Normalization with Kronos-Finetune

The goal is to match the tokenizer input pipeline of `Lpatchtst` with the one used in `Kronos_finetune`. Specifically, we will replace log-returns with raw OHLCV data and update the Z-score normalization to use a window size equal to the `LOOKBACK_WINDOW`.

## Investigation Summary
- **Current `Lpatchtst` Pipeline**:
    - Uses `prepare_ohlc_features` in `train.py` to compute log-returns of Open, High, Low, Close, Volume, and Amount (6 features).
    - In `data_loader.py`, `tokenize_full_series` uses a fixed window size `S = 64` for per-window Z-score normalization and as the input sequence length for the tokenizer.
- **`Kronos_finetune` Pipeline**:
    - Uses raw OHLCV + Amount values.
    - Performs Z-score normalization (Mean/Std) over a window equal to the `lookback_window`.
- **Key Constraints**:
    - `LOOKBACK_WINDOW` in `Lpatchtst` is 512.
    - We must avoid data leakage (ensure normalization for bar $t$ only uses data $\le t$).
    - The `KronosTokenizer` (Transformer-based) can handle variable sequence lengths, so increasing the window from 64 to 512 is architecturally feasible.

## Implementation Steps

### 1. Modify `train.py` to use raw OHLCV
Update `process_dataset` to stop using `prepare_ohlc_features` and instead extract raw OHLCV and compute Amount.

- Remove the call to `prepare_ohlc_features`.
- Implement raw extraction:
    - Identify columns for Open, High, Low, Close, Volume.
    - Compute `Amount = Close * Volume`.
    - Stack them into a NumPy array of shape `(N, 6)`.
- Ensure the resulting `ohlc_vals` are aligned with `feat_vals` and `target_vals`.

### 2. Update `data_loader.py` for Window-based Normalization
Modify `tokenize_full_series` to use the configured `LOOKBACK_WINDOW` for both normalization and input sequence length.

- Change `S = 64` to `S = getattr(config, "LOOKBACK_WINDOW", 64)`.
- The sliding window implementation using `as_strided` already ensures that for every bar $t$, the normalization and encoding use the window $[t-S+1, t]$, which prevents lookahead leakage.
- Keep the Z-score normalization logic (subtract mean, divide by std) as it matches the requirement.
- Ensure `TOKENIZER_CHUNK_SIZE` in `config.py` is sufficient to handle the larger sequence length (512) without OOM.

### 3. Verification and Cleanup
- Verify that `FinancialDataset` and `create_multi_index_dataloaders` correctly pass the raw OHLCV data to `tokenize_full_series`.
- (Optional) Remove or mark `prepare_ohlc_features` in `tokenizer.py` as deprecated if no other components use it.

## Data Leakage Guard
- The current `tokenize_full_series` implementation:
    1. Pads the start of the series.
    2. Uses `as_strided` to create windows of size `S`.
    3. Normalizes each window `(B, S, C)` across the `S` dimension.
    4. Extracts the token for the last element in the window `idx_c[:, -1]`.
- This ensures that the token for bar $t$ is derived from a window ending at $t$, using statistics calculated only from that window. This is leak-free.
